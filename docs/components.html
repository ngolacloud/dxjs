NgolaCloud · @dxjs/ui · CSP-safe

Components, class-only.

A styled, CSP-safe component kit for the NgolaCloud / Seiva console. Every component only toggles CSS classes — the look lives in a served stylesheet — so the whole kit runs under a strict CSP: no eval, no inline styles, escaped output.

$npm install https://github.com/ngolacloud/dxjs/releases/download/v__DXJS_VERSION__/dxjs-{core,dom,component,ui}-__DXJS_VERSION__.tgz

The @dxjs/* packages ship as tarballs on each GitHub Release; the @dxjs name on the npm registry belongs to an unrelated project.

Guide

Build a component from scratch

A dxjs component is a plain function: it takes an options object and returns a TemplateResult. Four rules keep it on-palette and CSP-safe.

1

Toggle classes, never inline styles

The look lives in a served stylesheet. A component sets class names with cx(...); it never writes a style attribute, so it satisfies style-src 'self'.

2

Take an options object with reactive accessors

Each prop is a plain value or an accessor. The Maybe type plus read() accept both, so a caller can pass a signal and the component stays live.

3

Bind through the safe sinks

Use @dxjs/dom's html: .value / .checked bind as live properties, @event is an addEventListener, ?attr toggles a boolean attribute — output is escaped, no eval.

4

Return a TemplateResult

Compose the markup and return it. Here is a dismissible tag chip, end to end.

→

Add the matching .dx-tag rules to the kit's stylesheet. Because styling is a served file, the same component renders identically in the browser and in CSP-safe string SSR.
