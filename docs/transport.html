dxjs is a tiny reactive framework with a protocol-neutral transport port. Describe an operation once; swap REST, gRPC, SSE, WebSocket or in-process by changing one line of bootstrap.

$npm install @dxjs/core @dxjs/dom @dxjs/transport

Overview

Small, reactive, honest about the network

A fine-grained signal graph renders the DOM, a string renderer does CSP-safe SSR, and the transport layer keeps your data-fetching code identical no matter what speaks on the wire.

σ

Fine-grained reactive

Signals, computeds and effects — no virtual DOM, no re-render pass. ~1.5 KB gzipped core.

⇄

Protocol-neutral

One method() descriptor; adapters map it to REST, Connect, SSE, WebSocket or in-process.

⛨

Strict-CSP SSR

String + streaming renderers escape every sink; no eval, no inline handlers, edge-ready.

Reactivity

The whole model, in twenty lines

A signal holds state, a computed derives from it, an effect runs when its reads change, and html / render bind the DOM to those reads — surgically.

Transport · ADR 0001

Describe the operation once

A method() is a protocol-neutral descriptor. A Transport adapter knows how to put it on a wire. createRpcClient gives you a typed call (unary) and live (server-stream) over whichever adapter you bootstrap with.

↳

Everything below reuses these exact descriptors. The only thing that changes between a REST deployment, a gRPC one, or a test is which adapter you pass to createRpcClient.

restAdapter

Typed JSON over HTTP — the everyday default.
unaryBearer authper-request headersretry · timeout
→Hits GET https://api.ngolacloud.ao/v1/users/42 with the bearer header; createUser becomes a POST with the JSON body. GET/HEAD/DELETE never send a body — set query: true on the wire to serialise the request as a query string.

connectAdapter

Connect / gRPC-web unary (JSON) to a gRPC service.
unaryConnect protocolBearer auth
→POST /user.v1.UserService/GetUser with a JSON body (Connect unary). The service and method are split from the descriptor id at the last dot.

sseAdapter

Server-Sent Events for live, server→client streams.
serverStreamauto-reconnectLast-Event-ID resumebounded buffer
→Opens text/event-stream at /v1/prices/KZ/stream via plain fetch (no EventSource, so custom headers & auth work). unary calls still go through REST; only streams use SSE.

wsAdapter

WebSocket for bidirectional, low-latency streams.
serverStreambidiauth frame first
→Browsers can't set an Authorization header on the WS handshake, so the adapter sends { type: "authorization", authorization: "Bearer …" } as the first message. Your server must authenticate that frame and emit nothing until it validates it.

inMemoryAdapter

In-process handlers — tests, demos, a monolith.
in-processunaryserverStreamno network
→Dispatches by the descriptor id to a local handler. Start as a monolith, then split into services later by swapping the adapter — the UI code never changes.

embeddedAdapter

dxjs running inside/next to the backend binary.
in-processunaryserverStreamhost dispatcher
→Every call goes straight to the host's invoke — fast (no network hop) and secure (no public surface). Ideal for co-located SSR; the same app also runs over restAdapter by swapping this one line.

Reactive data

resource() — a fetch that reacts

Wrap any transport call in a resource to get a reactive accessor with loading/error, cancellation, and idempotency-gated retries.

Reactive data

liveSignal — a value that stays live

A signal fed by the transport's native stream when it has one (SSE, WebSocket), and falling back to polling when it doesn't — the call site is the same either way.

Reactive data

openapiClient — typed from your spec

Point @dxjs/openapi at an openapi.json and get a client whose calls are validated against the request schema — over any adapter.

◆

Siblings @dxjs/soap and @dxjs/proto add SOAP and protobuf descriptors over the same port — the UI keeps calling api.call(...) regardless of what the server speaks.
