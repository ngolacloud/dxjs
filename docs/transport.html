One app.
Any backend.

dxjs is a tiny reactive framework with a protocol-neutral transport port. Bring a backend in Python, Go, Rust or Node — describe the operation once and connect from the frontend in three lines.

$npm install @dxjs/core @dxjs/dom @dxjs/transport
Connect a real backend → Run it in the browser

Overview

Small, reactive, honest about the network

A fine-grained signal graph renders the DOM, a string renderer does CSP-safe SSR, and the transport layer keeps your data-fetching code identical no matter what language the server is written in.

σ

Fine-grained reactive

Signals, computeds and effects — no virtual DOM, no re-render pass. ~1.5 KB gzipped core.

⇄

Protocol-neutral

One method() descriptor; adapters map it to REST, Connect, SSE, WebSocket or in-process.

⛨

Strict-CSP SSR

String + streaming renderers escape every sink; no eval, no inline handlers, edge-ready.

Quickstart · CLI

Run it in the browser

dxjs ships dxdev — a dev server with CSP-safe hot-module reload. Point it at an entry module and open the printed URL.

1

Write a tiny app

An entry module that renders reactive markup.

2

Start the dev server

Flags: --port, --host, --root, --css a.css,b.css, --title. In this repo, npm run dev is the shortcut.

3

Open the printed URL

Edit src/app.ts and the browser hot-reloads — no full refresh, signals survive.

$ npm run dev
dxjs dev server → http://127.0.0.1:5173/ (strict CSP, HMR)
▸ open http://localhost:5173

Reactivity

The whole model, in twenty lines

A signal holds state, a computed derives from it, an effect runs when its reads change, and html / render bind the DOM to those reads — surgically.

Transport · ADR 0001

Describe the operation once

A method() is a protocol-neutral descriptor. A Transport adapter knows how to put it on a wire. createRpcClient gives you a typed call (unary) and live (server-stream) over whichever adapter you bootstrap with.

Every adapter, one client API

All of these feed createRpcClient. Capability chips are the adapter's real runtime caps.

restAdapter

Typed JSON over HTTP — the everyday default.
unaryBearer authper-request headersretry · timeout

connectAdapter

Connect / gRPC-web unary (JSON).
unaryConnect protocolBearer auth

sseAdapter

Server-Sent Events — live server→client streams.
serverStreamauto-reconnectLast-Event-ID resumebounded buffer

wsAdapter

WebSocket — bidirectional, low-latency streams.
serverStreambidiauth frame first
→Browsers can't set an Authorization header on the WS handshake, so the credential is the first frame. Your server must authenticate it and emit nothing until it validates.

inMemoryAdapter

In-process handlers — tests, demos, a monolith.
in-processunaryserverStreamno network

embeddedAdapter

dxjs running inside/next to the backend binary.

Reactive data

resource() — a fetch that reacts

Wrap any transport call in a resource for a reactive accessor with loading/error, cancellation and idempotency-gated retries.

Reactive data

liveSignal — a value that stays live

Fed by the transport's native stream when it has one (SSE, WebSocket), and polling when it doesn't — the call site is the same either way.

Reactive data

openapiClient — typed from your spec

Point @dxjs/openapi at an openapi.json and get a client whose calls are validated against the request schema — over any adapter.

◆

Siblings @dxjs/soap and @dxjs/proto add SOAP and protobuf over the same port — the UI keeps calling api.call(...) regardless of what the server speaks.
